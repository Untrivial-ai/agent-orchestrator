# Staged update replacement

AO records updater provenance in `~/.ao/staged-update-journal.json`. The journal preserves the candidate that native Squirrel may have staged while a newer candidate is checked, downloaded, verified, and handed off. Windows and Linux promote a replacement after the updater completion boundary. macOS retains both candidates after ZIP delivery because native validation is still unknown.

The journal does not control Squirrel. Deleting or changing AO's record cannot revoke a native install request. Until the native boundary is addressed separately, quitting outside AO during a replacement may still install the older candidate. The renderer must keep that warning visible, and AO's Restart and Install action must remain disabled until the replacement becomes the staged candidate.

Writes use a same-directory temporary file, file synchronization, and atomic rename. POSIX platforms also synchronize the directory. Windows skips unsupported directory flushing; this does not promise POSIX-equivalent directory durability across power loss. Writes are serialized. A failed write keeps the live transition chain intact and blocks installation until its latest snapshot is persisted; an earlier queued success cannot clear that barrier. Invalid or unknown journal records are quarantined and logged instead of being interpreted as safe.


Integration with current main preserves #4849's restaging suppression, escalation clock, release notes and restart confirmation. The old `staged-update.json` record migrates into the journal; there is no parallel legacy writer and channel switches never discard A. A channel-switch replacement remains in the serialized operation even when automatic downloading is disabled. Same-channel discovery respects that preference and exposes an explicit Download action. Returning to A abandons B only if B never reached native handoff. Superseded candidates that reached native handoff remain recorded in `nativeCandidates`.

MacUpdater resolves its download promise when the loopback ZIP response finishes, before Squirrel validation. Neither that promise nor its earlier update-downloaded event proves B was accepted. This PR conservatively leaves macOS replacements in native-handoff with A/B provenance and AO restart disabled. Late native errors become replacement failures without losing A. Relaunch into the expected candidate reconciles the journal. A usable verified native completion signal and safe cancellation remain requirements for PR3; PR2 alone does not enable AO restart after a macOS replacement.

#4922's quit-time protection remains enabled on Windows and Linux while replacement is incomplete. On macOS the install-on-quit flag must remain enabled for the updater to hand the replacement to Squirrel; AO's own install entry point is guarded separately. Native cancellation and stronger native operation identity remain PR3 work. #4929 changes upstream PR-claim authorization and does not change the updater.
