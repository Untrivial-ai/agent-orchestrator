No account required. AO runs locally: the desktop app owns the daemon on your machine, and agent provider sign-ins stay with the CLIs you already use.

<InstallDownloads />

The desktop app is the canonical install path. It owns the local daemon, requires no global `ao` command, and checks for updates after launch and while it is running.

## Prerequisites

| Tool | When you need it | Why |
| --- | --- | --- |
| Git | Always | Creates and manages worktrees, branches, and (for standalone agents) AO-managed directories. Required to open the app. |
| An agent harness | Always | The coding agent AO launches, such as Claude Code, Codex, Cursor, Aider, or OpenCode. Required to open the app. |
| tmux | Terminal UI on macOS/Linux | Keeps native TUI sessions attachable. Chat does not require an agent tmux pane. Required on macOS/Linux at startup; Windows uses ConPTY instead. |
| GitHub CLI `gh` | GitHub PR and issue workflows | Lets agents open pull requests and read issues. **Advisory only** — AO does not block without it. See [When you're ready for a team of agents](/docs/team-of-agents). |

AO uses the agent binaries and sign-ins already installed on your machine. It does not bundle Claude Code, Codex, or other provider CLIs.

## Set Up AO

<Steps>
<Step>

### Install and open the desktop app

Choose the download for your platform above, install it, and open **Agent Orchestrator**. The app starts and supervises the local Go daemon automatically.

</Step>
<Step>

### Install and sign in to an agent

Install at least one supported agent harness and run it once outside AO to complete its sign-in flow. AO detects available harnesses when you create a session.

For structured Chat, start with Claude Code, Codex, OpenCode, or Droid. Other supported harnesses run through their native Terminal UI.

</Step>
<Step>

### Open a folder or start a standalone agent

In the desktop app, choose **Add a project** → **Import an existing project** and select a local folder, or drag a folder onto the window. AO registers the project without moving your original checkout.

Standalone agents need no repository: use **New standalone agent** for a branchless AO-managed directory. Full first loop: [Quickstart](/docs/quickstart).

</Step>
</Steps>

GitHub authentication is not part of first install. When you want pull requests, issue intake, or a GitHub remote during import, follow [When you're ready for a team of agents](/docs/team-of-agents).

## Where AO Stores Data

All AO application state lives under `~/.ao` by default, including the daemon database, run file, managed worktrees, Electron browser data, and mobile pairing configuration. Advanced installations can override daemon paths with `AO_DATA_DIR` and `AO_RUN_FILE`.

## Common Installation Problems

<Accordions>
	<Accordion title="No agent is available">
		Install a supported agent harness, run it once to authenticate, then restart AO so the desktop-launched daemon receives the updated login-shell environment.
	</Accordion>
	<Accordion title="GitHub data is missing">
		`gh` is optional for local Chat. When you need pull requests or issues, run `gh auth status` and follow [When you're ready for a team of agents](/docs/team-of-agents). Confirm the active account can access the repository.
	</Accordion>
	<Accordion title="Terminal UI cannot start on macOS or Linux">
		Install `tmux`, or choose Chat when the selected harness supports it.
	</Accordion>
	<Accordion title="The legacy `ao` command is not found">
		The desktop app does not require it. Only troubleshoot the package manager's global bin path if you intentionally use the frozen legacy CLI.
	</Accordion>
</Accordions>
