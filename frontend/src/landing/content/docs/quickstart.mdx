No account required. AO runs locally on your machine: the desktop app supervises a loopback daemon, and your agent CLIs and credentials stay yours.

This guide is the smallest useful first loop. GitHub authentication, multi-agent project setup, and the pull-request workflow come later — see [When you're ready for a team of agents](/docs/team-of-agents).

<Callout type="info" title="Before you start">
	Install the desktop app and at least one supported agent harness (Claude Code, Codex, OpenCode, Droid, or another adapter). See [Installation](/docs/installation). Git and an agent on `PATH` are required to open the app; `gh` is not.
</Callout>

## Run The First Loop

<Steps>
<Step>

### Download and open AO

Install Agent Orchestrator from [Installation](/docs/installation) and open the app. It starts and supervises the local Go daemon automatically. No AO cloud account and no global `ao` command are required.

</Step>
<Step>

### Open a folder

Choose **Add a project**, then **Import an existing project**, and pick a local folder — or drag a folder onto the app window. AO registers it without moving your checkout. A plain folder is fine; AO can initialize Git when the folder needs it.

Prefer not to attach a repository yet? Use **New standalone agent**. Standalone agents need no project or repository; AO gives them a branchless managed directory.

</Step>
<Step>

### Chat with one agent

From the project (or the standalone flow), choose **New task**. Give a short title and a concrete brief, select an installed harness, and start in **Chat** when the harness supports it (Codex, Claude Code, OpenCode, or Droid). Other harnesses use **Terminal UI**.

For a Git-backed project, AO creates an isolated worktree and branch before launching the agent. Standalone sessions stay branchless.

Keep the first prompt small:

```text
Explain the layout of this folder in a few bullets. Do not modify files yet.
```

Follow up in the Chat composer. Activity such as active, idle, waiting for input, blocked, or exited is derived from durable session facts.

</Step>
<Step>

### Pair your phone

On the same trusted Wi-Fi as the desktop:

1. Install the AO mobile app.
2. Open desktop **Settings → Connect Mobile** and enable mobile access.
3. Scan the pairing code in the mobile app (it fills address, port, and connection password). Enter the three values manually if you prefer.

Connect Mobile is opt-in, password-protected, and intended for a home network. Turning it off closes the LAN listener. Details: [Connect Mobile](/docs/configuration/remote-access).

</Step>
</Steps>

## GitHub Is Optional For This Loop

AO does **not** block the desktop app when GitHub CLI (`gh`) is missing or unsigned-in. Local Chat, Terminal UI, and standalone agents work without it.

You may see an advisory **Connect GitHub for pull requests** notice on the home board. Dismiss or ignore it until you want agents to open pull requests, read issues, or observe CI. Creating a GitHub remote during project import also needs GitHub access.

When you are ready for that workflow, continue with [When you're ready for a team of agents](/docs/team-of-agents).

## Optional CLI

The CLI is a thin client for the app-owned daemon. Useful for scripting; not required for the first loop.

```bash
ao status
ao session ls
ao send --session <session-id> --message "Summarize what you changed."
```

For a web task later, point the session Browser tab with:

```bash
ao preview http://127.0.0.1:5173
```
