## Short answer

Choose **Agent Orchestrator (AO)** when you want a local desktop and mobile supervisor that orchestrates existing coding agents through PR, CI, and review without standing up a hosted control plane. Choose **AgentsMesh** when a team needs distributed runners, shared channels, browser access, and remote agent workstations coordinated from a web control plane.

Both support multiple coding agents and Git worktree isolation. [AgentsMesh](https://agentsmesh.ai/docs) documents cloud control plus self-hosted runners; [AO](https://orchestrator.inc/docs/) keeps the daemon and application state under `~/.ao` on your machine (with an opt-in phone companion).

## What AO uniquely has

- **Local-first issue-to-merge loop** with a project orchestrator and CI/review routing.
- **Desktop on macOS/Windows/Linux** plus **iOS/Android** over Connect Mobile—no org signup required to start.
- **Apache-2.0**, ~25 harnesses, GitHub and GitLab, isolated browser per worker.
- Smaller operational footprint: open the app, add a repo, spawn workers.

## Where AgentsMesh is stronger

- **Distributed runners and remote AgentPods** across machines and cloud VMs.
- **Team/org collaboration primitives**: channels, tickets, shared bindings, browser access to remote workstations.
- A hosted control plane when you intentionally want agents away from a single laptop.

## At a glance

| Area | Agent Orchestrator | AgentsMesh |
| --- | --- | --- |
| Primary workflow | Local issue-to-PR agent supervision | Distributed team and AgentPod coordination |
| Control plane | Local loopback daemon and desktop supervisor | Web control plane with runner and relay infrastructure |
| Isolation | Local worktree or clone plugins | Sandboxed AgentPods with optional Git worktrees |
| Collaboration | Tracker, SCM, session, and notification surfaces | Organizations, teams, channels, tickets, and pod bindings |
| Feedback loop | CI and review events can wake the owning agent | Ticket and pod coordination through the platform |
| Mobile | iOS and Android companions (LAN) | Browser/remote workstation oriented |
| Best fit | Individuals and local-first project fleets | Teams operating agents across machines and cloud VMs |

## Frequently Asked Questions

### Do AO and AgentsMesh both keep model credentials under user control?

Yes. AO uses the credentials of installed agent CLIs directly. AgentsMesh documents a bring-your-own-key model with encrypted credentials.

### What is AO's main advantage over AgentsMesh?

AO offers a simpler local-first path with no required hosted control plane, plus a focused issue-to-PR automation loop—including phone check-ins against your desktop daemon.

### Is AO a hosted multi-user service?

No. The primary daemon listener stays on `127.0.0.1`. Connect Mobile is an explicit home-network companion, not a public multi-tenant cloud.
