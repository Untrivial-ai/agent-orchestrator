---
title: Issue tracking
description: Opt-in, read-only GitHub and GitLab issue intake.
---

AO has GitHub and GitLab issue adapters. The existing [GitHub intake guide](/plugins/trackers/github) explains the shared opt-in flow; choose `gitlab` for GitLab projects. Linear and external Node tracker plugins are unsupported.

Tracker intake needs both a per-project opt-in and the daemon-wide `AO_TRACKER_INTAKE` flag, which defaults off. Once both are on it can discover matching GitHub or GitLab issues and spawn workers, but v1 is read-only toward the tracker: AO does not comment on or transition issues as agent lifecycle changes.

<Callout type="warn">
	The tracker lane is still limited. Do not treat issue association as a complete two-way synchronization workflow.
</Callout>

Use the SCM capability for pull requests, CI, reviews, and mergeability; those facts are independent from tracker intake.
